# CLAUDE.md — память проекта «Ульяновский Швейцар»

Этот файл читается Claude Code автоматически. Здесь — весь контекст: что за проект, правила, архитектура, как деплоить, что сделано и что в планах.

## Что это
Бесплатный самохостируемый Discord-бот для RP-семьи **«Ульяновы»** (игра «Россия Онлайн», сервер «Арбатский»).
Хостинг: **bot-hosting.net** (бесплатный тариф, его надо продлевать каждые ~4 дня вручную).
Владелец: Никита (GitHub `mousetilt`, Discord-семья «Ульяновы»). Общение всегда **на русском**.

## 🔒 Железные правила (не нарушать)
1. **ТОЛЬКО бесплатное.** ИИ — Groq (`gpt-oss`) и Google Gemini (оба бесплатные ключи). TTS — Microsoft `edge-tts` + `gTTS` фолбэк. Распознавание — Groq Whisper. Никаких платных сервисов по умолчанию (OpenAI обсуждали — платно, максимум как 3-й резерв).
2. **Владелец/семья не должны лезть в код ВООБЩЕ.** Любая новая настройка — через Discord-команды (модалки для секретов), не через правку файлов. Это продуктовый принцип, цель — «пригласил бота, и он работает».
3. **Безопасность.** Никогда не реализовывать сбор паролей/почт/токенов, фишинг, скрытое сканирование дисков и т.п. (была попытка переименовать вредоносный .bat «под семью» — отказано). Панель управления (`maintenance.py`) НЕ выполняет произвольный код — только фиксированные действия.
   - **Единственное исключение (решение владельца, 2026.11.18):** аккаунт форума forum.russia.online, заведённый семьёй специально для бота, — вводит Глава/зам/владелец модалкой `/форум аккаунт`. Бот этим аккаунтом ТОЛЬКО читает (никаких постов, лайков, ответов). Пароль (`forum:pass`) — секрет: не показывать, не логировать, вырезается из ВСЕХ копий базы (`daily.make_backup`). Чужие пароли/куки/токены по-прежнему не собирать. Риск: правило форума 2.3 (мультиаккаунт → бан всех аккаунтов) — владелец предупреждён, решение за ним.

## Архитектура
- `bot.py` — точка входа.
- `core/botcore.py` — `FamilyBot` (наследник commands.Bot). Загружает коги из `config.EXTENSIONS`. Модель: **один «домашний» сервер** (полный функционал, `bot.home_guilds`) + **альянс-сервера** (только ког `alliance`). События с неродных серверов роутятся только в Alliance.
- `core/config.py` — конфиг. Секреты из окружения: `DISCORD_TOKEN`, `GROQ_API_KEY`, `GEMINI_API_KEY`, `AI_PROVIDER` (сейчас `gemini`), `GUILD_ID`. Хардкод семьи/структуры тоже тут (это блокер мультисемейности, см. планы).
- `core/db.py` — sqlite, один коннект, схема v2 (`PRAGMA user_version=2`). **Все таблицы семьи с `guild_id`** — в каждом запросе фильтровать по серверу. Настройки сервера (роли `role:*`, каналы `ch:*`, панели `panel:*`, прозвища `alias:*`…) — в `guild_settings`, доступ `db.gget(guild, key)` / `db.gset(guild, key, value)` (guild может быть Guild/Member/int). Глобальное — `db.get/set` в `settings`: только `home_guild`, `hub:*`, `whisper:*`, `tts:*`, `alliance_charter`, `bot_avatar_set` (список в `GLOBAL_KEYS/GLOBAL_PREFIXES`). Старая база мигрирует сама при старте (копия `*.bak-v1`). Общие для всех семей документы базы знаний — `kb_docs.guild_id=0` (правила проекта/ООС). Выборки по уникальному id записи/сообщения/канала (кнопки бота) можно без `guild_id`.
- `core/ai.py` — ИИ с фолбэком: цепочка моделей провайдера + резервный провайдер; кулдаун на модель при лимите (`cool`), пометка мёртвых (`dead`). `ask()`/`ask_json()`.
- `cogs/` — фичи (см. ниже).

## Ключевые коги
- `assistant.py` (самый большой) — ИИ-чат и ДЕЙСТВИЯ: бот отвечает в чате и выполняет команды (музыка, ЛС, напоминания, законы, рынок, войс и т.д.) через JSON-actions от ИИ. `USERS` — привилегированные роли. `SYSTEM`/`SYSTEM_LITE` — промпты.
- `persona.py` — характер: досье на людей (−100..+100), злопамятный (отношение само не растёт), настроение по времени. Проведывает одиноких в войсе (с 08:00 до 02:00 МСК), встречает входящих. `/досье`, `/забудь_меня`, `/любимчики`.
- `jarvis.py` — «голосовой Швейцар» (`/швейцар`, ког по-прежнему называется `Jarvis`): слушает войс, распознаёт через Whisper (лимит: 1800/сутки + 18/мин), выполняет голосовые команды. Слышит всех семьи по очереди: `Listener.todo` + `worker()` — первым тот, кто позвал (приоритет 0), руководство (1), остальные (2: только последняя фраза, старше 20 с — выкидывается, из минутного лимита им не достаётся `OWNER_RESERVE`). `say()` — озвучка.
- `music.py` — музыка + TTS (`announce()` сам заходит в войс, говорит, выходит). Голос `ru-RU-DmitryNeural`.
- `moderation.py` — ИИ-модерация (пакетами, на младшей модели).
- `maintenance.py` 🆕 — панель владельца: `/статус`, `/перезапуск` (через `os.execv`), `/обновить` (git pull + рестарт), `/модуль <имя>` (reload). Только Глава/зам.
- `hub.py` 🆕 — `/помощь`, `/панель`, панель участника, раннер кнопок → команд (Фаза 1).
- Прочее: `applications` (заявки), `diplomacy`, `alliance`, `market`, `mentorship`, `interviews`, `boosts`, `streams`, `appeals`, `server_setup`, `daily`, `lawyer` (законы РО), `context_menus`.

## Ошибки бота → разработчику → Claude
- `cogs/errorwatch.py`: `ErrorCollector` (logging ERROR+) → таблица `bot_errors` (подпись «тип+код Discord+место в нашем коде», повторы — `count`), шум сети отсеивается (`NOISE`), секреты/ID вычищаются (`clean`). Раз в 10 мин новые → ЛС разработчику (`dev:user`, по умолчанию владелец домашнего сервера) + файл `errors.txt`; если задан токен (`/разработчик github`, `dev:gh_token`/`dev:gh_repo`) — issue с меткой `bot-error`.
- **В начале сессии с Claude:** проверить новые ошибки. Репозиторий публичный — читать без токена: `curl -s "https://api.github.com/repos/mousetilt/family-discord-bot/issues?labels=bot-error&state=open"`. Если станет приватным — нужен `gh` (`winget install GitHub.cli`, `gh auth login`), тогда `gh issue list --label bot-error`. Починил → в коммите `Fixes #N` (закроет задачу) → запись в changelog.
- Или владелец пересылает файл `errors.txt` из ЛС бота прямо в чат.

## Форум-монитор (суды и жалобы)
- Разделы жалоб/судов/прокуратуры, «Законодательная база» (1471) и указы (1474) с ноября 2026 **закрыты для гостей**
  (403 + страница «Вход»). `core.kb` распознаёт это (`LoginRequired`) — повторять бессмысленно.
- `core/forum.py`: `ForumClient` (вход XenForo: `/login/` → `_xfToken` → POST `/login/login`, пауза 2 с между ЛЮБЫМИ
  запросами, одна сессия, перезаход при вылете), `SECTIONS` (id раздела → название, тип, статус), разборщики
  `parse_forum_list`/`parse_thread_page`, поиск: `surname_rx` (фамилия во всех формах + латиница), `titles_rx`
  (должности Главы), `analyze` (роль: defendant/plaintiff/witness/mention по меткам «Ответчик:», «vs», ближайшему
  маркеру; статики из списка — тоже повод). `LoginError` — без смены данных не повторяем (`forum:auth_fail`).
- `cogs/forumwatch.py`, модуль `forum` (watch · ping), по умолчанию ВЫКЛ (включается при вводе аккаунта). Таблицы
  `forum_threads` (кэш: last_ts/seen_ts), `forum_cases` (дело: role, status, message_id карточки, dthread_id ветки,
  body — текст жалобы, decision — последний ответ; для юриста), `forum_people` (ручной список + `head`). Ростер — ники
  и анкеты семьи с фамилией. Цикл: 1-я стр. каждого раздела (при первом проходе — 2 стр., старше 30 дн. не читаем),
  ≤30 тем за цикл, ответчик → карточка + пинг, остальное — тихий лог. Известные дела из ТЗ — `seed` (домашний сервер,
  один раз). Канал `forumwatch` «⚖・суды-и-жалобы» (`AUTO_CHANNELS` + `OPTIONAL_CHANNELS`: сборка создаёт только при
  включённом модуле). Ключи: `forum:login/pass/interval/titles/ignore/surname/last/last_err/seeded`.
- Для юриста (`ForumWatch.harvest`, в том же цикле, если модуль `lawyer` вкл): **практика** — рассмотренные/
  отклонённые темы по 3 за цикл (`forum_threads.harvested`) + дела семьи с решением → `kb_docs` раздел `practice`;
  **формы** — закреплённые темы судов/прокуратуры (`SECTION_TEMPLATE`) раз в неделю → раздел `forms`; **законы**
  1471/1474 (`LAW_SECTIONS`) — список раз в 3 дня, ≤8 тем за цикл, документ обновляется на месте по id темы
  (`kb_put`, без дублей, хоть общий guild_id=0), изменения по статьям (`legal.diff_line`) → бот-команды + канал
  юриста (первая загрузка — молча, флаг `forum:laws_init`). `ForumWatch.fetch_doc` — закрытая тема для `/база`.

## ИИ-юрист (`cogs/lawyer.py` + `core/legal.py`)
- `answer_full(gid, q, mode, member, template, clarify)` → {text, sources, ai, mode, questions}; `answer()` — старая
  обёртка (3 значения) для assistant/context_menus/mentorship. Режимы: q · case · doc · **defense** (сам включается,
  если член семьи спрашивает про своё дело — `ForumWatch.cases_context`).
- Поиск: `legal.expand_query` (УК, КоАП, ДМ, ВС…), статья, о которой спросили по номеру, — +12 к весу куска.
- Самопроверка: `legal.verify` — каждая «ст./п. N [код]» сверяется с базой (код → документ по названию,
  `title_fits`), выдуманные помечаются ⚠️ + предупреждение внизу.
- Уточнения: case/doc/defense (и длинные сообщения в канале юриста) — сначала `CLARIFY` (ask_json, light): 1–3 вопроса
  → `ClarifyView` (модалка ответов / «разобрать как есть»).
- Документы: `/юрист документ:` (8 типов `legal.TEMPLATES`, поля [..]); если есть реальная форма с форума
  (раздел `forms`) — даётся она.

## Альянс: семьи без бота
- `alliance_families.external=1`: семья без нашего бота, живёт в штабе. `guild_id` — условный отрицательный (`EXT_BASE=-1000` и ниже), `leaders` — JSON Discord ID руководства (голосуют из штаба), участники — роль `hub:fam:<gid>` в штабе (выдаёт их руководство: `/альянс участники добавить|убрать|руководство`). Принимается голосованием: `/альянс добавить-семью` (нужен штаб).
- Приём без голосования: `Alliance.is_founder` (Глава/зам/владелец домашнего сервера) → `force_accept` (открытые голосования по заявке → passed, `activate`, запись в летопись). `/альянс принять-сразу` (автодополнение заявок), `/альянс добавить-семью сразу:True`.
- Рассылка `broadcast`: семьи без бота пропускаются; нет канала → один раз `build_hub`/`ensure_channels` и повтор; что не дошло — `last_failed` (log.error → отчёт разработчику). `start_vote(..., fallback=канал)` + `where_sent()` для ответа автору. `/альянс голосования` — голосовать без канала совета.
- ВАЖНО: `bot.is_home(None) == True` — для таких семей проверять `Alliance.is_ext(row)` раньше, чем `is_home(get_guild(...))`.

## Деплой
- Хостинг bot-hosting.net: файлы в `/home/container`, секреты — во вкладке «Окружение» (НЕ в .git). Запуск: `pip install -r requirements.txt && python3 -u bot.py`.
- **Через GitHub:** правим код → `git push` → в Discord `/обновить` (бот делает `git fetch`, показывает список коммитов и перезапускается через `launcher.py`).
- **`launcher.py`** — стартовый файл на хосте (`STARTUP_FILE=launcher.py` в «Конфигурации запуска»; саму команду запуска хоста не трогаем). На каждом старте: есть git → `fetch` + `reset --hard origin/main` (при первом запуске сам делает `git init` в папке), нет git → качает zip с codeload.github.com. Игнорируемые файлы (`*.db`, `.env`, `.local`) не трогает. Если изменился `requirements.txt` — ставит зависимости. Любая ошибка → стартует на текущем коде. `start.sh` — старый вариант, не используется.
- Git на этом ПК: `C:\Program Files\Git\cmd\git.exe` (не в PATH у сессии Claude). Авторизация GitHub — через Git Credential Manager, уже выполнена.
- `.gitignore` исключает `.env`, `*.db`, логи, кэш — секреты в репозиторий не попадают. Репозиторий: `github.com/mousetilt/family-discord-bot` (public).
- Тест перед деплоем: `python -m unittest discover -s tests` (в т.ч. загрузка всех когов на офлайн-боте) — должно быть без ошибок; то же делает GitHub Actions.

- Речь: действия `treasury_*`/`dues_set` в `assistant.py` (промпт `ACT_TREASURY` подмешивается только тем, кто в TREASURY, и если модуль включён); запись — после «Выполнить», справки — сразу. Логика — `Treasury.speech()`/`describe()`.
